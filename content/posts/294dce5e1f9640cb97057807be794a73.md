## 问题现象

在 Android 16 系统中集成 `WallpaperPicker2`（位于 `/system_ext/priv-app/WallpaperPicker2`）后，设备无法正常启动，log 中报错：

```text
E System : java.lang.IllegalStateException: Signature|privileged permissions not in privileged permission allowlist: {com.android.wallpaper (/system_ext/priv-app/WallpaperPicker2): android.permission.SET_WALLPAPER_DIM_AMOUNT}

```

## 问题原因

- `WallpaperPicker2` 作为特权应用（priv-app）声明了 `android.permission.SET_WALLPAPER_DIM_AMOUNT` 权限，该权限属于 `signature|privileged` 级别。

- Android 要求所有特权应用声明的此类权限必须显式加入**特权权限白名单**（通过 XML 文件配置），否则 PackageManager 会在启动时拒绝授予权限并抛出异常，导致系统无法启动。

- 由于 `WallpaperPicker2` 安装在 `/system_ext` 分区，其权限白名单也必须放置在对应的 `system_ext` 目录下（`/system_ext/etc/permissions/`），而不能放在 `/system/etc/permissions/` 中，否则系统无法识别。

## 解决方法

### 1. 创建权限白名单 XML 文件

新建一个文件，例如 `privapp-permissions-wallpaperpicker2.xml`，内容如下：

```xml
<?xml version="1.0" encoding="utf-8"?>  
<permissions>  
    <privapp-permissions package="com.android.wallpaper">  
        <permission name="android.permission.SET_WALLPAPER_DIM_AMOUNT"/>  
    </privapp-permissions>  
</permissions>
```

### 2. 将文件编译到正确分区

在设备的 `device.mk` 或 `product.mk` 中添加拷贝规则，**必须使用 `TARGET_COPY_OUT_SYSTEM_EXT` 指定输出到 system\_ext 分区**：

```makefile
PRODUCT_COPY_FILES += \  
device/<厂商>/<设备>/privapp-permissions-wallpaperpicker2.xml:$(TARGET_COPY_OUT_SYSTEM_EXT)/etc/permissions/privapp-permissions-wallpaperpicker2.xml
```

**关键点**：

- 目标路径中的 `$(TARGET_COPY_OUT_SYSTEM_EXT)` 确保文件最终被放置在 `/system_ext/etc/permissions/` 目录下。

- 如果误将文件拷贝到 `$(TARGET_COPY_OUT_SYSTEM)/etc/permissions/`（即 `/system/etc/permissions`），系统仍会报同样的错误，因为 system\_ext 分区的特权应用只会扫描本分区内的白名单。

### 3. 重新编译并刷机

执行完整编译（如 `m -j8`），生成新镜像后刷机，设备即可正常启动。

## 注意事项

- 确保 XML 中的 `package` 属性值与应用的包名完全一致（本例为 `com.android.wallpaper`）。

- 如果权限名称拼写错误，需检查应用 `AndroidManifest.xml` 中的实际声明。

- 若已有针对 system\_ext 的全局权限配置文件（如 `privapp-permissions-system_ext.xml`），也可将权限条目直接添加进去，避免新增文件，但同样需确保文件被编译到 system\_ext 分区。

- 不同分区（system、system\_ext、product）的特权应用需要对应的白名单文件放置在同一分区下，否则权限授予失败。
